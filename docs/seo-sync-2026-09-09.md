## Pasos en WordPress después del despliegue del tema

El push a GitHub sincroniza código, no la base de datos de WordPress. Los scripts siguientes se ejecutan desde un checkout administrativo, porque `tools/` se excluye del ZIP de producción.

1. Ejecutar `wp eval-file tools/seo-sync-menu.php` para revisar los cambios de enlaces persistidos. Ejecutar de nuevo con `apply` para aplicarlos con copia de los valores anteriores. Solo modifica enlaces custom cuyo destino se pueda resolver; preserva menús personalizados y enlaces de objetos WordPress.
2. Ejecutar `wp eval-file tools/seo-create-service-drafts.php`, y después con `apply` para crear los dos borradores. Revisar en WordPress, publicar y añadir al menú cuando sus URLs estén disponibles. Nunca sobreescribe páginas existentes.
3. Revisar individualmente `docs/seo-priority-routes.json` contra las rutas actuales antes de aprobar Salou, Andorra y Cadaqués y ejecutar `tools/seo-approve-routes.php`. Sus marcas editoriales siguen en `false`; no representan una migración completada.
4. La limpieza de posts reciclados, Tax Free y la ampliación de la FAQ general requieren seleccionar las entradas y revisar contenido vigente. No se borran posts ni se reactivan generadores de contenido automático desde el tema.
5. El enfoque nacional está implementado en la landing principal; no se generan páginas masivas de destinos. El rollout EN conserva la aprobación por variante; añadir texto en español a una plantilla no certifica una traducción revisada.

## Paquete de producción

Desde PowerShell: `./tools/build-release.ps1`. Empaqueta el commit HEAD, no archivos sin commit. Se puede indicar `-Ref` y `-OutputPath`. El script rechaza sobrescrituras y verifica archivos necesarios y exclusiones. GitHub Actions adjunta `metransfers-theme` después de los controles.

El ZIP excluye Git, herramientas, pruebas, documentación, cachés y dependencias de desarrollo. Composer solo declara PHP como requisito de producción; el tema dispone de autoloader propio en `app/Bootstrap.php`, por lo que no necesita el `vendor/` de herramientas.

## Validación

Se ejecutan PHPUnit, PHPStan, WPCS, regresiones locales y validación del archivo de producción. Las pruebas HTTP con WordPress real se ejecutan en GitHub Actions; Docker Desktop no estaba iniciado en el entorno local. El resultado remoto debe comprobarse antes de integrar.
